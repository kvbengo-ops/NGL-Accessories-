## Findings

### Critical

**1. Anyone can likely register as an admin.**
- Live auth settings: `disable_signup: false`, `mailer_autoconfirm: true` (public endpoint `/auth/v1/settings`, read-only). Anyone can create a confirmed account with no email check.
- `handle_new_user` (`supabase/migrations/20260914000000_schema.sql:214`) inserts every new auth user into `admins` with `is_active = true`. `is_admin()` and all admin RLS policies only check for an active row.
- Impact: a self-registered user can read all orders and customer details, edit products, prices and stock, and change expenses and tasks.
- Not verified: the live trigger definition, and no signup was attempted. The repo's own notes (`security-hardening.sql` C2, `audit-fixes.sql:300`) list "disable public sign-ups" as a manual step; the live setting shows it was not done.
- Fix: (a) make the trigger insert `is_active = false`, or remove it; (b) move admin creation out of the browser: `src/admins.js:200` calls `supabase.auth.signUp` client-side, which breaks once sign-ups are off, so use a server function that calls the Supabase admin API; (c) then disable sign-ups in Authentication → Providers.

### High

**2. Stored XSS in places that render admin-entered text as HTML without escaping.** `escapeHtml` is used in 13 files and missing from these:
- `src/shop.js:292-293` (product name, description) and `:163` (toast), `src/search.js:149`: public storefront.
- `src/inventory.js:55,81`, `src/pos.js:33,160,354`, `src/expenses.js:142-143`, `src/tasks.js:102,175-176`: admin panel.
- Impact: a lower-privileged admin, or the attacker from finding 1, can inject script that runs for a superadmin or for every shopper. The old QA report marked XSS fixed, but only `orders.js` and `dashboard.js` were covered.
- Fix: escape every interpolated string, or set `textContent`.

**3. Several tables are open to any logged-in user, not just admins.**
- `contact_messages` (`...0700:37`), `reviews` (`...0800:37`), `shipping_zones` and `province_zones` (`...0200:92,98`) still use `auth.role() = 'authenticated'`. The audit-fixes migration only converted the earlier tables to `is_admin()`.
- Combined with finding 1, a self-registered user can read contact messages and change shipping fees.
- Fix: replace with `public.is_admin()` checks, as `audit-fixes.sql` did for the other tables.

**4. Payment screenshots are publicly readable.**
- The `payment-proofs` bucket is public; the only protection is an unguessable URL (`...0300_payment-proof.sql`). `security-hardening.sql` already lists making it private as a follow-up.
- Fix: private bucket plus signed URLs in the admin order view.

**5. `/api/support` has no abuse protection and leaks internals.**
- `worker.js` has no origin check or rate limiter for `/api/support` (the stylist endpoint has both). The only limit is 12 messages per minute per conversation, and `support_start` can create unlimited conversations, so a script can run up LLM and Supabase usage.
- `functions/api/_support-core.js` returns `envKeys: Object.keys(env)` in a 500 response (lists server variable names). `worker.js` also returns raw error text from Supabase.
- `conversation_id` is placed into PostgREST URLs without UUID validation. I do not think it can expose other conversations (the token check still applies), but it should be validated.
- Fix: reuse the `STYLIST_LIMITER` pattern, add an Origin check, return generic errors, validate the UUID.

### Medium

**6. Icons do not render on `admin/try-on.html`.** The page has no Material Symbols font link, and `src/admin.js` draws the sidebar icons with that font, so they show as plain words. Same cause as the earlier `try-on.html` bug. The other admin pages load the font.

**7. Reflected input.** `src/search.js:134` puts the search text into `innerHTML` unescaped, and the shop accepts `?search=` from links.

**8. Most `SECURITY DEFINER` functions in the first six migrations have no `SET search_path`** (for example `create_order_safely`, `update_admin_password`, `set_admin_role`, `get_order_status`). Later migrations set it. This is a hardening gap, not a known exploit.

**9. `update_admin_password` writes straight to `auth.users`.** The audit-fixes notes already say to use the Supabase admin API instead.

**10. SEO and metadata gaps.**
- `public/sitemap.xml` lists 6 pages; `try-on.html` is not included.
- Canonical links are missing on checkout, contact, privacy, terms, support, track-order, try-on, review and 404.
- `index.html` and `order-confirm.html` have no meta description.
- `try-on-lab.html` is a dev page that is not built into `dist` but is still in the repo.

**11. `QA_Audit_Report.md` is stale.** It says all 18 items are complete.

### Low

- Build warning about the `supabase.js` dynamic import (see Automated checks).
- CI does not run `tests/test-support-grounding.mjs` or `tests/test-api.js`.
- `src/supabase.js:157` still has the placeholder GCash number `09XX-XXX-XXXX`. Confirm real values are set in Admin → Store Settings.
